# Play redesign — 2026-10-24

Scope: only `gheimat-shenas-play`. Original main project and previous reference studio were not changed.

Implemented requests:

1. Daily reward days are sorted newest first and rendered RTL; today is selected at the physical right.
2. No decorative splash, spinner sequence or shimmer screen. Real pending requests retain an inline state and disable duplicate actions. Fonts never gate the interface.
3. Official DigiCoin asset downloaded unchanged from https://www.digikala.com/statics/img/svg/superapp/supercoin/hub/coin.svg (referenced by Digikala's own public frontend).
4. Compact mobile layouts and paginated history. Verified normal target dimensions without internal page scrolling. At extreme zoom / very short heights the accessibility fallback allows scrolling instead of clipping content.
5. Independent desktop home, two-column gameplay arena, centered dialogs, desktop result and tutorial layouts.
6. Tier names are included in each badge ribbon in home, guide, celebration and result surfaces.
7. A complete five-stage animated tutorial: reference price → hidden comparison → choice → price reveal and score → promotion to next reference. Includes pause, replay, direct step controls and reduced-motion handling.
8. No earned badge under the first checkpoint, including zero records. Neutral encouraging copy explains how to earn the first badge.
9. 1080×1350 share card with local typography, record, earned title, new artwork, game name and exact Play URL. Preview, file download and native sharing where supported. No catalog photos enter the canvas, avoiding cross-origin export failures.
10. New generated price-tag / up-down logomark.
11. New generated 3D home illustration, optimized to about 96 KB WebP.
12. Full product titles without CSS clamp, hidden overflow or ellipsis. Product images use contained boxes with explicit minimum sizes.
13. Vivid coral, cobalt and midnight palette. Primary red adjusted to meet 4.5:1 against white; blue / success / secondary text also exceed 4.5:1.
14. Fixed missing result balance, missing last-comparison recap, modal keyboard escape and infinite font-wait failure. Untimed continuation decision is implemented in the simulator, not merely hidden visually.
15. Automated simulator and browser checks accompany the source.

## Validation

- Browser played a run through all 20 checkpoint answers, claimed all four tiers, then timed out, continued for 5 simulated coins and intentionally missed the next question. All-time record and named badge appeared on home.
- Home, ready / active question, result, all checkpoint tiers, tutorial and badge guide were inspected. Daily today position was measured as the rightmost cell. Tab focus cycles inside the leave dialog.
- DOM layout fixture checks all 989 catalog titles with the real view functions. 360×640, 390×844, 430×932 and 1280×720 passed with no detected clipping / overflow in the fixture. 768×1024 was not verified after the browser connection stalled; no tablet-specific pass is claimed. These are layout checks, not a guarantee that all remote image URLs load.
- Simulator tests exercise 21 correct answers, rewards +9, no repeated charges, continuation preserving score, cap enforcement, offer recovery after 10 minutes, failed / unknown charge resolution, daily claim idempotency, insufficient balance, question timeout and share URL.
- Share PNG generated by the actual module was downloaded and visually inspected at 1080×1350.
- No live DigiCoin wallet, real payment, native Super App bridge, Safari or actual iOS/Android hardware was tested.

## Remaining product issues

- Existing copy claiming a player is smarter than 50/70/90/99 percent of people has no statistical evidence in this demo. It is preserved from the agreed game copy; replace with factual checkpoint celebration copy before public release unless research substantiates it.
- Slow or failed remote product images can still arrive after the authoritative question timer starts. This implementation keeps the full product name visible; a fair server-backed image-readiness policy requires a separate API decision. It must not silently reset the timer or grant extra time on the client.
- The simulator stores one account in localStorage. Multiple open tabs are not a real multi-client backend; use one game tab per browser while reviewing. This limitation predates the redesign.
